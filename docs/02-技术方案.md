# 技术方案

决策依据见 [ADR-0001](决策/0001-用Unity与SoundTouch做本地复读.md)。范围见 [01-范围与验收.md](01-范围与验收.md)。

## 结论

功能级复读可以做：动画状态、变调学说话、触摸打断。像素级复制官方 Tom 形象不作为目标。版权和美术资源是主要约束，不是算法。

## 主路径

Unity（C#）移动端，本地 SoundTouch 变调，Animator 驱动角色。

| 模块 | 选型 | 说明 |
|---|---|---|
| 工程 | Unity 2022.3 LTS 或 Unity 6 LTS，URP | 一套工程出 Android / iOS |
| 角色 | 自有或 Asset Store 可商用 3D 卡通猫 | 可先用占位体 |
| 动画 | Animator Controller | Idle 为默认；Talk 按时长结束 |
| 录音 | Unity Microphone → PCM | 全离线 |
| 切句 | 能量门限 | 不用语音识别 |
| 变声 | SoundTouch，只改 Pitch | 语速保持 1；起步约 +7 半音 |
| 播放 | AudioSource | 播放期间关闭麦克风 |
| 交互 | Collider + 触摸射线 | 戳击打断当前复读 |

Flutter 或纯 Web 可以做演示，但 3D 角色、触摸打断和后续口型在 Unity 里更完整，因此不作为主工程。

## 数据流

```
麦克风 → 能量切句 → SoundTouch → AudioSource
                              ↓
                        Animator（Talk）
触摸 → 停止播放 → 反应动画 → 回到监听
```

## 可行性边界

| 能力 | 结论 |
|---|---|
| 变调复读 | 可做 |
| 听 / 说 / 闲置切换 | 可做 |
| 戳击打断 | 可做 |
| 口型跟句子时长 | 可做；先不做逐字口型 |
| 听感接近 | 靠真机调参，不靠模拟器 |
| 官方形象 | 不追求 |
| 教古诗、语音识别、大模型 | 不在第一版 |
| 养成、商城、广告 | 不在第一版 |

## 约束

- 没有正式模型时用占位体推进录音，不把美术当成写代码的前置条件
- 音高、切句和防回录只认真机结果
