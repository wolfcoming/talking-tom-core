# 文档怎么用

这是一个人也能维持的正规拆法：**状态、范围、方案、执行、决策分开**。不要把它们写进同一个文件，也不要为每个小步骤单独建文件。

## 每天实际怎么做

1. 打开 [`开发进度表.md`](../开发进度表.md)，看哪一个里程碑是「进行中」。
2. 只打开该里程碑文件，做里面还没勾的下一项。
3. 做完就勾选。参数、机型、失败现象写在该文件底部的「执行记录」。
4. 回到进度表改一行：状态、阻塞、日期。
5. 该里程碑的验收全部勾完，状态改为「已完成」，再把下一个里程碑改为「进行中」。

同一时间只允许一个里程碑处于「进行中」。被环境、资源或缺陷挡住时，状态写成「阻塞」，在备注里写原因，不要另开一份文档。

## 五类文档，各管一件事

| 文档 | 多久改一次 | 放什么 |
|---|---|---|
| [开发进度表.md](../开发进度表.md) | 每天 | 只记状态：未开始 / 进行中 / 阻塞 / 已完成 |
| [01-范围与验收.md](01-范围与验收.md) | 范围变化时 | 做什么、不做什么、怎样算过关 |
| [02-技术方案.md](02-技术方案.md) | 架构变化时 | 模块、数据流、约束 |
| [里程碑/](里程碑/) | 做该阶段时 | 步骤、做法、交接句、执行记录 |
| [决策/](决策/) | 做一次选择时 | 为什么这样选；旧决策不改写，只标记被替代 |

## 为什么不把每一步拆成一个文件

准备、切句、变调、打断都是同一条复读管线上的连续步骤，分开后每天要打开十几个文件，状态会和做法对不上。正规项目里，这些步骤是**同一个里程碑里的任务清单**。

下面情况才新建文件：

- 新的里程碑（例如以后做养成）
- 一次会长期生效的技术选择，写入 `决策/`
- 某个模块反复修改，需要单独的设计说明

临时报错、某次手感试验，写在当前里程碑的执行记录里。
